# Личный дневник

Веб-приложение для ведения личного дневника на Django.
Пользователи могут создавать, просматривать, редактировать и удалять
свои записи. Интерфейс реализован на Django Templates и Bootstrap.

## Возможности

- Регистрация с подтверждением email шестизначным кодом.
- Вход по email и паролю, выход из аккаунта.
- Повторная отправка кода и продолжение незавершённой регистрации.
- Приветственное письмо после подтверждения email.
- Создание, просмотр, редактирование и удаление записей.
- Поиск по заголовку и содержимому.
- Сортировка: сначала новые или сначала старые записи.
- Пагинация по 10 записей.
- Отображение общего количества своих записей.
- Изменение никнейма и необязательного номера телефона.
- Переключение видимости пароля при вводе.
- Управление пользователями и записями через Django Admin.

На пользовательских страницах каждый пользователь имеет доступ
только к своим записям. Подстановка ID чужой записи возвращает 404.
Суперпользователь управляет данными через отдельную административную панель.

## Технологии

- Python 3.14
- Django 5.2
- PostgreSQL 17
- Redis 7.4
- Celery
- Django Templates и Bootstrap 5.3
- Poetry
- Docker и Docker Compose
- Flake8, Black, isort
- GitHub Actions — автоматические проверки и сборка Docker-образа

Точные версии Python-зависимостей зафиксированы в `poetry.lock`.

## Требования для запуска

- Docker с поддержкой Linux-контейнеров.
- Docker Compose v2.
- Свободный локальный порт 8000.
- Интернет для первоначальной сборки и загрузки Bootstrap через CDN.
- Ящик Mail.ru с паролем приложения для отправки писем.

На Windows можно использовать Docker Desktop.

Python, Poetry, PostgreSQL и Redis отдельно устанавливать
для запуска через Docker не требуется.

## Подготовка настроек

Скачайте или клонируйте репозиторий и откройте терминал
в корне проекта — в папке с `docker-compose.yml`.

Создайте `.env` на основе `.env.example`.

В PowerShell:

```powershell
Copy-Item .env.example .env
```

В Linux или macOS:

```bash
cp .env.example .env
```

Не выполняйте копирование поверх уже настроенного `.env`,
если хотите сохранить текущие настройки.

Заполните переменные:

```dotenv
SECRET_KEY=replace_with_generated_secret_key

DB_NAME=personal_diary
DB_USER=diary_user
DB_PASSWORD=replace_with_database_password
DB_HOST=127.0.0.1
DB_PORT=5432

CELERY_BROKER_URL=redis://127.0.0.1:6379/0

EMAIL_HOST=smtp.mail.ru
EMAIL_PORT=465
EMAIL_USE_SSL=True
EMAIL_HOST_USER=your_address@mail.ru
EMAIL_HOST_PASSWORD=replace_with_app_password
```

Заглушки для ключа, паролей и адреса почты необходимо заменить.

Внутри Compose адреса базы и брокера переопределяются:
Django и Celery подключаются к `db:5432` и `redis:6379`.

Файл `.env` не должен попадать в Git.

### Генерация SECRET_KEY

Если Python установлен локально:

```bash
python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Либо через Docker:

```bash
docker run --rm python:3.14-slim python -c "import secrets; print(secrets.token_urlsafe(64))"
```

Скопируйте результат в `SECRET_KEY` в `.env`.
Ключ генерируется один раз для окружения, а не при каждом запуске.

### Настройка Mail.ru

В настройках безопасности почты создайте пароль для внешнего приложения
с доступом «Только отправка писем в Почте».

В `EMAIL_HOST_USER` укажите полный адрес ящика,
а в `EMAIL_HOST_PASSWORD` — пароль приложения.

Обычный пароль от почтового аккаунта не используется.

Без работающей отправки почты новый пользователь не сможет
завершить подтверждение регистрации.

## Запуск

Запустите Docker Engine, затем выполните:

```bash
docker compose up -d --build
```

Compose запускает следующие сервисы:

| Сервис | Назначение |
|---|---|
| `db` | PostgreSQL |
| `redis` | Брокер сообщений Celery |
| `migrate` | Применение миграций |
| `web` | Django |
| `worker` | Выполнение фоновых задач |

Сервис `migrate` должен завершиться с кодом 0.
После успешных миграций запускаются `web` и `worker`.

Проверка состояния:

```bash
docker compose ps -a
```

Адреса:

- Главная страница: http://127.0.0.1:8000/
- Дневник: http://127.0.0.1:8000/diary/
- Регистрация: http://127.0.0.1:8000/users/register/
- Вход: http://127.0.0.1:8000/users/login/
- Админка: http://127.0.0.1:8000/admin/

Текущая конфигурация предназначена для локального запуска:
Django работает через сервер разработки, порт доступен только
на локальном компьютере.

## Создание администратора

```bash
docker compose exec web python manage.py createsuperuser
```

Администратор создаётся активным через команду.
Вход в админку выполняется по email и паролю.

## Подтверждение email

1. После регистрации создаётся неактивный аккаунт.
2. Celery отправляет письмо с кодом через SMTP Mail.ru.
3. Пользователь вводит код на странице подтверждения.
4. После правильного кода аккаунт активируется и выполняется вход.
5. В очередь ставится приветственное письмо.

Правила:

- Код состоит из 6 цифр.
- Срок действия — 10 минут с момента запроса.
- Разрешено 5 неверных попыток.
- Повторный запрос — не чаще одного раза в минуту.
- Новый код заменяет предыдущий.
- В PostgreSQL хранится хеш кода.
- Код передаётся worker через очередь Redis.
- После потери сессии регистрацию можно продолжить по ссылке
  «Не подтвердили почту?» на странице входа.

## Проверки и тесты

Проверка конфигурации:

```bash
docker compose exec web python manage.py check
```

Запуск тестов:

```bash
docker compose exec web python manage.py test users diary
```

Тесты используют отдельную тестовую базу.
Они проверяют права владельца, назначение владельца при создании,
правила подтверждения email и продолжение регистрации.

## Проверка стиля Python-кода

Инструменты разработки устанавливаются локально через Poetry.
Нужна версия Python, совместимая с `pyproject.toml`.

```bash
poetry install --with dev --no-root
```

Проверки без изменения файлов:

```bash
poetry run isort . --check-only
poetry run black . --check
poetry run flake8 .
```

Автоматическое форматирование:

```bash
poetry run isort .
poetry run black .
```

Настройки Black и isort находятся в `pyproject.toml`,
настройки Flake8 — в `.flake8`.

В текущем Docker-образе установлены только основные зависимости.
Инструменты группы `dev` в него не включены.

## Автоматические проверки — GitHub Actions

Workflow находится в `.github/workflows/ci.yml`.

Проверки запускаются при отправке коммитов в `main`, `develop`
и ветки `feature/**`, а также при создании и обновлении
pull request в `main` или `develop`.

Этапы:

1. Установка Python 3.14 и зависимостей через Poetry.
2. Проверка форматирования Black и порядка импортов isort.
3. Проверка кода Flake8.
4. Проверка конфигурации Django.
5. Проверка отсутствия изменений моделей без миграций.
6. Запуск тестов.
7. Сборка Docker-образа после успешного прохождения проверок.

Для проверок запускаются временные PostgreSQL и Redis.
Рабочая база проекта и настоящие почтовые пароли не используются.
Почтовый backend сохраняет тестовые письма в памяти процесса.

Celery worker в CI не запускается. Доставка писем через SMTP
этими проверками не проверяется.

Результаты доступны во вкладке Actions репозитория на GitHub.
Workflow проверяет сборку образа, но не публикует его
и не выполняет развёртывание на сервере.

## Полезные команды

Обычный запуск:

```bash
docker compose up -d
```

Запуск после изменения кода, шаблонов или зависимостей:

```bash
docker compose up -d --build
```

Перезапуск без обновления кода:

```bash
docker compose restart
```

Журнал Django:

```bash
docker compose logs -f web
```

Журнал Celery:

```bash
docker compose logs -f worker
```

Последние сообщения всех сервисов:

```bash
docker compose logs --tail=100
```

Остановка:

```bash
docker compose down
```

Код копируется в образ во время сборки.
Обычный перезапуск контейнеров не подхватывает изменения файлов проекта.

## Хранение данных

PostgreSQL хранит данные в именованном томе `postgres_data`,
Redis — в `redis_data`.

Команда `docker compose down` сохраняет тома.
Команда `docker compose down -v` удаляет их вместе с данными.

Контейнерная база не переносит автоматически данные из локального PostgreSQL.

Параметры `POSTGRES_DB`, `POSTGRES_USER` и `POSTGRES_PASSWORD`
используются при первоначальной инициализации пустого тома.
Изменение `.env` не меняет пароль уже существующего пользователя PostgreSQL.

## Если письмо не пришло

- Проверьте папку «Спам».
- Убедитесь, что worker запущен.
- Проверьте журнал `docker compose logs --tail=100 worker`.
- Проверьте адрес отправителя и пароль приложения Mail.ru.
- После изменения `.env` пересоздайте контейнеры:

```bash
docker compose up -d --force-recreate web worker
```

Успешная постановка задачи в очередь не гарантирует доставку письма.
При ошибке отправки можно запросить новый код после окончания
интервала повторной отправки.
